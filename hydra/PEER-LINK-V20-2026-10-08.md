## Remaining steps (in order)

1. **Gateway restart on V20** (James approval) — applies the `0.0.0.0` bind so the listener is LAN-visible.
   `hermes -p default gateway restart`
2. **Inbound firewall rule** (needs an ELEVATED shell — Mez is not elevated; a plain attempt fails):
   ```
   netsh advfirewall firewall add rule name="Hermes peer api_server 8642" dir=in action=allow protocol=TCP localport=8642 remoteip=192.168.4.0/22 profile=private
   ```
   Scoped to the LAN subnet, private profile only — not the world.
3. **Register the peer from V20** once Ubuntu's `API_SERVER_KEY` is supplied (out-of-band; it is a credential):
   `hermes peer set ubuntu --url http://192.168.4.40:8642` with `HERMES_PEER_UBUNTU_KEY` in `.env`
   or `hermes peer add max --url http://192.168.4.40:8642 --key <ubuntu's key>` if James wants the peer named `max`.
4. **Ubuntu side** (for the reverse direction): register V20 with V20's own API_SERVER_KEY, read on the Ubuntu box.

## Test after step 2

From the Ubuntu box: `curl -s -o /dev/null -w "%{http_code}\n" --max-time 5 http://192.168.4.44:8642/v1/models`
Expect **401** (reachable, unauthorised) — that proves inbound TCP works. `000` means still blocked.
