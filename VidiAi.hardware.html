The ASUS Pro WS WRX90E-SAGE SE is a workstation motherboard built for AMD Threadripper Pro 7000WX series processors. It provides 128 PCIe 5.0 lanes directly from the CPU, enabling up to 7 GPUs at full x16 bandwidth simultaneously.

Multi-GPU AI inference servers, rendering workstations, and scientific computing. The 128-lane topology means every GPU slot runs at full PCIe 5.0 x16 speed.

Why It Matters

This is the only motherboard that supports 4+ GPUs at full x16 bandwidth. For AI inference with large models, PCIe bandwidth directly impacts token generation speed.

Why WRX90? - PCIe 5.0 x16 Matters for Multi-GPU AI

In AI inference, PCIe bandwidth directly impacts how quickly model weights can be loaded from system RAM to GPU VRAM during context pre-filling. When running a 72B parameter model across 4 GPUs, each GPU needs to receive ~18GB of weights. At PCIe 4.0 x8 speeds, this takes significantly longer than at PCIe 5.0 x16.

Air Gap Strategy - Slots 1, 3, 5, 7

When installing 4 GPUs in a 7-slot chassis, use slots 1, 3, 5, and 7. This leaves one empty slot between each card, creating an air gap that prevents heat from one GPU from being sucked into the next card's intake.

Blower cards pull air from the front and exhaust it directly out the rear. Air gaps prevent heat recirculation between adjacent cards.

Hermes Agent

Persistent AI agent with skills, memory, and tool use. Your always-on AI assistant.

What Is It?

Hermes Agent is a persistent AI agent framework that maintains cross-session memory, learns from interactions, and executes skills (tools) to accomplish tasks. It runs locally on your sovereign AI node, connecting to your local LLM via llama-server.

What People Use It With

Paired with Qwen 72B for complex reasoning tasks, Mem0 for long-term memory, and CrewAI for multi-agent orchestration. Integrates with LTX Desktop as the user-facing interface.

Why It Matters

Hermes transforms your AI node from a simple model server into an intelligent assistant that remembers context, learns your preferences, and autonomously executes multi-step workflows. It's the "brain" of your sovereign AI stack.

CrewAI

Role-based agent orchestration. Deploy teams of AI agents with specialized skills.

What Is It?

CrewAI is a framework for orchestrating multiple AI agents, each with defined roles, goals, and tools. Agents collaborate to solve complex tasks that require diverse expertise.

What People Use It With

Combined with LangGraph for deterministic workflow control, Hermes for agent memory, and local LLMs (Qwen 72B) for reasoning. Popular for medical AI pipelines where different agents handle intake, analysis, and verification.

Single-agent systems hit limits on complex tasks. CrewAI lets you deploy a "Medical Review Board" of specialized agents - each running on your local hardware - that collaborate to produce more accurate, auditable results.

LangGraph

Deterministic workflow engine. Ensures AI agents follow exact execution paths.

What Is It?

LangGraph is a framework for building stateful, multi-step AI workflows as directed graphs. It ensures agents follow predetermined paths with explicit state transitions - critical for medical and compliance applications.

What People Use It With

Works with CrewAI for agent orchestration, PydanticAI for data validation, and local LLMs. Essential for HIPAA-compliant medical AI pipelines where every step must be auditable.

Why It Matters

In medical AI, you can't afford "hallucination loops." LangGraph ensures your agents follow the exact workflow: Intake > Analysis > Verification > Output. Every step is logged, every transition is validated.

vLLM / llama.cpp

High-performance inference backends. Serve models via OpenAI-compatible API.

What Is It?

vLLM and llama.cpp are the two primary inference engines for running LLMs locally. llama.cpp (with llama-server) provides CPU+GPU inference with GGUF format support. vLLM offers high-throughput GPU serving with PagedAttention.

What People Use It With

llama.cpp is the go-to for GGUF models (Q4-Q8 quantization) on Intel GPUs. vLLM excels at high-concurrency serving. Both expose OpenAI-compatible APIs for seamless integration with agent frameworks.

Why It Matters

These are the engines that power your AI node. llama.cpp's GGUF format enables efficient Q8_0 quantization on Intel XMX, while vLLM's PagedAttention maximizes throughput for multi-user deployments.

Frequently Asked Questions

I have $5K, what do I buy?

Start with the 3-card B70 build ($5,800). You'll get 96GB VRAM - enough to run Qwen 72B at Q4_K_M quantization. If budget is tight, start with 2 cards ($1,900) and add more later. The WRX90 board supports up to 7 GPUs, so you can scale incrementally.

I have $10K, what do I buy?

Go for the 5-card B70 build ($7,900) and use the remaining $2,100 for upgrades: add more RAM (256GB DDR5 ECC ~$900), larger NVMe (8TB ~$600), or better cooling (Noctua industrial fans ~$150). You'll have 160GB VRAM for maximum model capacity.

I have $30K, what do I buy?

Build the 5-card B70 ($7,900) and invest the rest in: dual-node setup (two 4-card builds for redundancy), enterprise networking (10GbE switches), UPS backup, or a 4x RTX 6000 Ada setup if you need NVIDIA-specific features. For most sovereign AI use cases, the 5-card B70 is the sweet spot.

What model should I run for medical use?

Qwen 72B at Q8_0 quantization is the best choice. It has exceptional medical knowledge, strong reasoning capabilities, and fits in 72GB VRAM (4-card B70 setup). For higher throughput, run Qwen 32B at Q8_0 (32GB) for faster responses on simpler queries. Use YaRN for extended context when processing large medical documents.

How do I set up llama-server on WSL?

1. Install WSL2 with Ubuntu. 2. Install Intel GPU drivers for WSL. 3. Build llama.cpp from source with IPEX-LLM support: cmake -DGGML_SYCL=ON .. 4. Download your GGUF model. 5. Run: llama-server -m model.gguf -c 8192 --host 0.0.0.0 --port 8080. 6. Access via browser at http://localhost:8080. The server exposes an OpenAI-compatible API for Hermes Agent and other tools.

How do I connect Hermes Agent?

1. Install Hermes Agent via pip: pip install hermes-agent. 2. Configure it to point to your llama-server: set LLM_URL=http://localhost:8080/v1. 3. Enable Mem0 for persistent memory: mem0 init. 4. Define skills (tools) in the Hermes config. 5. Start the agent: hermes start. 6. Connect LTX Desktop to the Hermes API at http://localhost:8000. Your agent is now ready for conversations.
