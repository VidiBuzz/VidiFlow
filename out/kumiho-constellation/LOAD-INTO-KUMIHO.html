2. The mapping: nodes.json / edges.json → Kumiho

Kumiho already stores everything as :Item (discriminated by a kind property) plus versioned :Revision nodes, grouped by :Project / :Space, with relationships CONTAINS (Space→Item) and HAS_REVISION (Item→Revision). The loader adds nothing to that schema — it only uses it.

Constellation data Kumiho object Exact call
node (id, name, kind, props) :Item in the space space.create_item(item_name=<slug of id>, kind=<node kind>)
node text/metadata :Revision on that item item.create_revision(metadata={…}, embedding_text=<summary/text>, idempotency_key=<stable>)
item props item metadata (string→string) item.set_metadata({…})
edge (source, target, type) Revision → Revision relationship source_rev.create_edge(target_rev, "DERIVED_FROM", metadata={…}, idempotency_key=…)

Key technical facts that the loader encodes:

  • Edges live between revisions, not items. create_edge(source_revision, target_revision, …). The loader therefore creates one revision per node and wires edges to those revisions.
  • Edge types must match ^[A-Z][A-Z0-9_]{0,49}$ (validated by both the SDK and the Rust server). Lower-case input like belongs_to is normalised to BELONGS_TO. Kumiho's own standard types are BELONGS_TO, CREATED_FROM, REFERENCED, DEPENDS_ON, DERIVED_FROM, PRODUCED_BY, MIGRATED_FROM, CONTAINS, SUPERSEDES, SUPPORTS; any other uppercase type in that pattern is accepted.
  • kref format: kref://<project>/<space>/<item_name>.<kind>?r=<revision>. House convention is dotted slugs — item names in the live graph look like ten-projects-into-revka-agent-os.goal, i.e. item_name = slug, kind = goal. The loader passes slug + kind separately and lets Kumiho form the dotted name.
  • Idempotency: create_revision and create_edge take idempotency_key; the loader derives deterministic keys (sha1 of node id / edge triple) so re-running the load is safe — the same input produces the same nodes and edges, not duplicates. Item identity is the (space_path, item_name, kind) triple, which Kumiho merges on.
  • Every edge carries source + confidence (house rule), and every loaded object carries source = "vidibot.constellation" so verification can find exactly what this load created.
  • kind = "bundle" is reserved by Kumiho; the loader renames any node that asks for it.
