Core Technology Architecture

The 3D Visual Vector Graph RAG System

This is the foundational innovation that powers everything we build. Without all three components working together, the system loses its core value.

1. pgvector (PostgreSQL) - The Mathematical Brain

  • Stores embeddings: 1,536 numbers per video/image
  • Performs similarity calculations
  • Finds semantically related content
  • Invisible to humans - pure mathematics
  • Cannot be queried or understood directly

2. Neo4j - The Knowledge Structure

  • Stores explicit, named relationships between content
  • Makes vector data comprehensible and queryable
  • Examples of stored relationships:
    • "Video X CONTAINS Product Y"
    • "Product Y COMPETES_WITH Product Z"
    • "Manufacturer SUPPLIES Product A"
    • "Content piece TARGETS audience segment B"
  • Enables human understanding of what's in the vector database
  • Prevents duplication - tracks what content exists and connections
  • Powers Smart Channel - knows what's been created, from what angles

3. 3D Force Graph (Three.js) - The Visualization

  • Visual representation of Neo4j relationships
  • Interactive exploration of content landscape
  • Client-facing sales tool - shows the invisible
  • Demonstrates semantic opportunities
  • Justifies premium pricing by making abstract concepts tangible

Why All Three Are Essential

The Problem We Solve: Vector embeddings are invisible to humans. 1,536 numbers mean nothing to a client. Without Neo4j and visualization, the vector database is "invisible magic" that clients can't understand, validate, or pay premium prices for.

The 3D Visual Vector Graph RAG Query Flow:

  1. Upload content → Generate embedding → Store in pgvector
  2. Extract entities (products, topics, concepts) → Store in Neo4j as nodes
  3. Create relationships → Store in Neo4j as edges
  4. Query combines both databases:
    • Neo4j: "Get all videos containing Product X"
    • pgvector: "Of those, which are most similar to this search query?"
  5. Visualize results → Show clients their content's semantic landscape in 3D

Business Impact:

  • Makes ROI tangible - "Here are 47 content opportunities we identified"
  • Enables Smart Channel - Knows what content exists, prevents duplication
  • Drives premium pricing - Clients see and understand the value
  • Competitive moat - Almost nobody has built this for SMBs

This 3D Visual Vector Graph RAG system is our raison d'être. It transforms invisible vector data into actionable, visual, queryable knowledge that drives content multiplication.

Database Strategy

Three-Database Hybrid System

Database Purpose When to Add
PostgreSQL + pgvector (Neon) • Structured data (users, videos, campaigns)
• Vector embeddings (22K+ vectors)
• Geographic queries (33K cities) 		Phase 0 - Start here
Neo4j AuraDB • Knowledge graph relationships
• Multi-hop reasoning
• Prevent content duplication
• Explainable AI 		Phase 0 - Essential for visualization
Qdrant Cloud • High-performance vector search
• Sub-100ms queries
• Millions of vectors 		Phase 3 - At 50K+ vectors

Why three databases? pgvector alone fails at scale due to performance limitations and lack of graph traversal capabilities. Neo4j can't handle vector similarity efficiently. Qdrant lacks relationship mapping. Together they form the complete 3D Visual Vector Graph RAG system.

Phase 0 Decision: Start with PostgreSQL + pgvector + Neo4j

  • 22,300 vectors well within pgvector capacity (22K images + 300 videos)
  • Neo4j essential for relationships and visualization
  • Migrate to Qdrant only when approaching 50K+ vectors
