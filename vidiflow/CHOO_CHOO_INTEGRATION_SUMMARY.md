# Choo Choo Engine: Visual Flow Matrix & Hermes Agent Integration Summary

This document provides a comprehensive archive of the structural and visual improvements applied to the high-density parallel agent flow dashboard (`CHOO_CHOO_PREVIEW.html`), along with the critical roadmap for connecting it as a live, fully-functional operational front-end for the **Hermes AI Agent**.

---

## 1. Summary of Completed Improvements

We have executed a series of visual, structural, and mathematical upgrades to ensure the interface operates with clinical precision, visual depth, and responsive stability.

### 📐 Visual Alignment & Center Tracing
* **Eliminated Coordinate Drift**: Replaced desynchronized hardcoded loop drawing logic (which limited movement to the left half of the viewport and drifted off visual rails) with strict mathematical binding. Active agents now follow the exact `computeAgentPosition` coordinate solver.
* **Cubic Bezier Alignment**: Glued the visual centers of the traveling agent nodes perfectly to the horizontal rails, circular roundabout arcs, and custom Cubic Bezier S-curve merging paths. Nodes remain centered on the lines at all screen widths.
* **Vertical Offset Lock**: Fixed the stationed stack blocks and travelling agent templates to align perfectly on their respective track lines (adjusting node offsets exactly to `y - 13` for 26px height containers).

### 🖥️ Full-Width Responsive Rails
* **Container-Width Math**: Replaced all absolute pixel bounds with dynamic, container-relative width calculations (`W = container.clientWidth`), enabling the ingress, roundabout center, egress tracks, fusion gates, and target stations to automatically span the full screen width.
* **Liquid Window Resize Handler**: Integrated window resize triggers that instantly recalculate SVG coordinate meshes, rebuild the path nodes, and re-draw existing stationed stacks.

### ⛓️ Locked Parallel Lane Routing
* **Crossover Prevention**: Configured deterministic egress branch-to-outflow mapping (`outflowTrack = Math.min(2, trackId)`), locking agents to their dedicated parallel lanes to prevent cluttered track-crossings.
* **Visual Stack Spacing**: Designed a continuous 2D progress-based collision/overlap resolver, spacing out travelling data segments smoothly behind target stations.
* **Filmstrip Timeline Presentation**: Retained timeline presentation symbols (`🎞️`) and incremental timecodes (`00:00`, `00:02`, etc.) in the chronological stack blocks.

## 2. To-Do List: Next 10 Actions for Hermes Agent Integration

To transition this preview from a simulated dashboard into a high-fidelity, production-grade telemetry front-end for **Hermes Agent** (and its Ollama/AppFlowy backend), we must execute the following 10 functional integrations:

### 1. Establish AppFlowy SQLite Database Telemetry
Create a light background polling process (or WebSocket listener) connecting the dashboard to the local SQLite database (`C:/appflowy/db`). This will feed real-time agent transaction logs and vector insertion events directly into the "AppFlowy Sync" telemetry card.

### 2. Inject Active Local AI Proxy (Port 11435) Requests
Connect the dashboard directly to the local Flask-based Ollama middleware. When the Hermes Agent makes reasoning steps, the dashboard should intercept prompt/response token streams, dynamically updating the **LLM Multi-Agent Core** token rate counter (`Tokens/s`).

### 3. Replace Simulated Data Modalities with Real Payload Routing
Map the active media modality selector buttons (**OCR Doc**, **Video Seg**, **Voice**, **Visual**, **Image**) to actual input streams in the Hermes Agent workspace. Selecting a mode should query corresponding tables (`af_research_vault_db`) to load real document metadata into the telemetry drawer.

### 4. Build Live WebSocket Event Broker
Replace the recursive setTimeout simulation cycles (`runSequentialWorkflow`) with a bidirectional WebSocket connection (`ws://localhost:11435/telemetry`). The Hermes runner will emit structured JSON events (`ingress`, `reasoning`, `compiling`, `deploying`) to animate matching agent cars in real time.

### 5. Render Real-Time "Visual Screenshot" Wireframes
Upgrade the dynamic UI zoom browser frames at the far-right of each track to render real screenshots or actual HTML wireframes generated by the Hermes Agent during layout rendering. We will use a fast Base64 canvas-renderer to display raw UI updates inside the mock browser component.

### 6. Map Hydraulic Pistons to Deployment Affirmations
Synchronize the high-tech hydraulic piston animations to trigger only when the Hermes Agent completes a successful compilation check. The physical piston drop and push should visually represent the writing of a finalized record into the database or hosting server (e.g. SiteGround).

### 7. Implement Interactive Step-by-Step Debug Controls
Create a "Step Debugger" interface on the sidebar, allowing engineers to pause, rewinds, or single-step the agent's flow through the RAG context engine, LLM core, sandboxed compiler, and release pipelines.

### 8. Feed Console Logs into the Floating Drawer
Wire up the right-hand inspection details panel to show live, streaming terminal stderr/stdout logs from the active agent execution thread, including syntax diagnostics and Ollama model context parameters.

### 9. Build a Deployment Verification Gate
Integrate deployment validation checks within the third compiler lane ("CI/CD Compiler Loops"). When testing, the agent node should only be pushed past the Fusion Gate after passing a mock syntax validation run (e.g., verifying `verify_bounds` and `parser.py` files).

### 10. Implement Custom Stimulus Diagnostic Injections
Upgrade the "Inject Activity Stimulus" button to send custom prompt payloads directly to the active Hermes process, triggering immediate, visible parallel processing spikes across all 4 visual tracks.
