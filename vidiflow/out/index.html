Before you accept anyone’s number — including this one — you must match all six of these. If any differs, the comparison is meaningless:

  1. Dense or MoE, and if MoE, the active parameter count — not the total.
  2. Speculation depth (MTP on/off, draft depth, acceptance rate).
  3. Quantization — Q4_K_M, Q5_K_XL, Q6, IQ4_NL and oQ6e are not the same bytes.
  4. Context length — decode falls off a cliff past 128K.
  5. Batch size — single-stream vs aggregate. They differ by multiples.
  6. Engine and version — two years of llama.cpp work is worth ~25% on its own.

The teaching formula

decode tok/s ≈ bandwidth ÷ model bytes

Decode is memory-bound: every token streams the active weights once through the memory system. Prefill is compute-bound — that's why tiny models feel instant and huge ones crawl on slow pipes.

Capacity vs speed

Fit = weights (×1.1 alloc overhead) + KV cache + 2 GB OS headroom. Multi-GPU pools add 10% NCCL overhead. MoE models allocate all parameters but decode only the active experts.

The offload lesson

Push the model past the pool and watch the bottleneck chain flip to PCIe: tok/s collapses ~30× because host RAM funnels through ~64 GB/s links instead of 1,792–22,000 GB/s of memory.
